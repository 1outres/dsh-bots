# Gmail と Google カレンダーをボットで使い始める

この手順で、ボットがあなたの Google アカウントの Gmail と Google カレンダーを使えるようになります。
ボットは Google にあなたのアカウントとしてアクセスしますが、**メールの送信・返信・転送、ゴミ箱、フィルタ、参加者のいる予定の作成・変更・削除、出欠の返答は、あなたが許可するまで実行されません**（Web UI のトレイ、または Discord の承認者の DM で許可します）。

必要なもの:

- DSH に `@1outres/dsh-bots` バンドル（または `@1outres/dsh-bot-core` と `@1outres/dsh-bot-connector-google`）が入っていること。
- DSH の Web UI をブラウザで開ける URL（例: `https://dsh.example.com`）。Google から DSH に直接届く必要はありません（リダイレクトはあなたのブラウザが行います）。ただし Google は **https で、IP アドレスではないホスト名** のリダイレクト URI しか受け付けません（`http://localhost` は例外）。
- Google アカウント（個人の Gmail でも Workspace でも可）。

所要時間は 15 分ほどです。

## 1. Google Cloud のプロジェクトを作る

1. <https://console.cloud.google.com/> を開き、上部のプロジェクト選択から **新しいプロジェクト** を作ります（名前は例えば `dsh-bots`）。
2. 作ったプロジェクトを選んだ状態で、**API とサービス → ライブラリ** から次の 2 つを検索して **有効にする** を押します。
   - Gmail API
   - Google Calendar API

## 2. OAuth 同意画面（Google Auth Platform）を設定し、本番に公開する

1. **API とサービス → OAuth 同意画面**（新しいコンソールでは **Google Auth Platform**）を開き、**開始** を押します。
2. アプリ情報: アプリ名（例: `DSH bots`）、ユーザーサポートメール（自分）を入れます。
3. 対象: **外部（External）** を選びます。（Workspace の組織内だけで使うなら「内部」でも構いません。個人の Gmail アカウントは「外部」でなければ使えません。）
4. 連絡先: 自分のメールアドレスを入れて作成します。
5. **データアクセス（スコープ）**: 追加しなくても動きます（DSH がサインインのたびに必要なスコープを要求します）。追加する場合は次のとおりです。
   - `openid`、`.../auth/userinfo.email`、`.../auth/userinfo.profile`
   - `https://www.googleapis.com/auth/gmail.modify`（メールの読み取り・ラベル・下書き・送信・ゴミ箱。完全削除はできません）
   - `https://www.googleapis.com/auth/gmail.settings.basic`（フィルタの一覧・作成・削除）
   - `https://www.googleapis.com/auth/calendar.events`、`.../auth/calendar.calendarlist.readonly`、`.../auth/calendar.freebusy`
6. **ブランディング（Branding）** を埋めます。外部（External）のアプリは、ここが揃わないと公開できません（「アプリを公開するには、[ブランディング] ページで構成を完了する必要があります。」と出て、公開のボタンが押せません。足りない項目の表示は出ません）。
   1. ホームページとプライバシーポリシーを、**誰でも見られる** Web サーバーに置きます。ひな形は [google-oauth-pages/](google-oauth-pages/README.md) にあります（運営者名・連絡先・制定日・利用者の範囲を、README の手順で書き換えてください。日本語版と英語版があります）。リダイレクト URI と同じドメインの下に置くと、承認済みドメインが 1 つで済みます。例: `https://example.com/dsh-bots/` と `https://example.com/dsh-bots/privacy`。VPN の内側など、外から見られない場所には置けません。
   2. **アプリのドメイン**: アプリケーションのホームページとプライバシーポリシーのリンクに、上の URL を入れます。利用規約は空で構いません。
   3. **承認済みドメイン**: ホームページのドメインと、リダイレクト URI のドメインを、トップのドメインで入れます（例: `example.com`。`dsh.example.com` も `example.com` に含まれます）。
   4. **デベロッパーの連絡先情報**: 自分のメールアドレスが入っていることを確かめます。
   5. **アプリのロゴは空のまま** にします（ロゴを入れるとブランドの審査が必要になります）。
   6. **保存** します。
7. **対象（Audience）→ 公開ステータス** で **アプリを公開（Publish app）** を押し、「本番環境（In production）」にします。
   - **「テスト」のままにしないでください。** テスト中のアプリでは、許可から 7 日でリフレッシュトークンが失効し、ボットがアカウントを使えなくなります（毎週つなぎ直しが必要になります）。とりあえず動作を確かめるだけならテストのままでも使えます（**対象 → テストユーザー** に自分のアカウントを足します）。
   - 公開しても Google の審査（検証）は申請しなくて構いません。未検証のまま、あなた（と数人）が使うぶんには動きます。ユーザー数の上限は 100 人です。サインインのときに「このアプリは Google で確認されていません」の警告が出ます。
   - Workspace のアカウントだけを使うなら、手順 3 で **内部（Internal）** を選べば、ブランディングも公開も要らず、7 日の失効もありません（個人の Gmail はつなげません）。

## 3. Web アプリケーション型の OAuth クライアントを作る

1. **API とサービス → 認証情報 → 認証情報を作成 → OAuth クライアント ID**（新しいコンソールでは **Google Auth Platform → クライアント → クライアントを作成**）。
2. アプリケーションの種類: **ウェブ アプリケーション**。名前は自由です。
3. **承認済みのリダイレクト URI** に、DSH の **dsh-bots の設定 → アカウント** に表示される URI をそのまま追加します。形は次のとおりです。

   ```
   https://<DSH を開くときのホスト名>/bot-core/oauth/callback
   ```

   例: `https://dsh.example.com/bot-core/oauth/callback`。DSH を複数のアドレスで開くなら、そのすべてを追加します（サインインはその画面のアドレスで行われます）。
4. 作成すると **クライアント ID** と **クライアント シークレット** が表示されます。この 2 つを次で使います（シークレットは他人に見せないでください）。

## 4. DSH に OAuth クライアントを設定する

1. DSH の Web UI で、左の **ボット** の見出しにある歯車（**dsh-bots の設定**）を開きます。
2. **アカウント** の **Google の OAuth クライアント** に、クライアント ID とクライアント シークレットを入れて **保存** します。
   - シークレットは DSH の認証情報ストア（このマシンのファイル）に保存され、画面にもボットにも表示されません。
   - 状態が「アカウントをつなげます。」になれば完了です。

## 5. アカウントをつないでボットに割り当てる

1. ボットのメニューから **設定… → コネクター** を開きます。
2. **Google アカウント** の **Google アカウントをつなぐ** で、許可するもの（Gmail、Google Calendar）を選び、必要なら名前（例: `仕事`）を入れて **Google でサインイン** を押します。
3. 新しいタブで Google のサインイン画面が開きます。アカウントを選ぶと「このアプリは Google で確認されていません」と表示されるので、**詳細 → （アプリ名）に移動（安全ではないページ）** を選び、要求された権限のチェックをすべて入れて **続行** します。
4. 「Google account connected」と表示されたらタブを閉じます。DSH の画面は自動で更新され、アカウントが「接続済み」になり、このボットに割り当てられます。
   - 別のボットでも同じアカウントを使うときは、そのボットのコネクター設定で **このボットで使う** にチェックを入れます（サインインし直す必要はありません）。
   - 複数のアカウントをつなげます。ボットはツールの `account` 引数（メールアドレスか名前）でどのアカウントを使うか選びます。
5. 同じ画面の **Gmail** と **Google Calendar** のカードで **このコネクターを使う** にチェックを入れ、**保存** します。
6. 必要ならイベント（新着メール、予定の追加・変更・取り消し）の届け方を選びます。
   - **ボットのメインセッションに知らせる**: 1 分ほどまとめて、ボットに通知します。
   - **ボットが取りに来るまで溜める**: ボットが `gmail_events_list` / `gmail_events_ack`（カレンダーは `gcal_…`）で取りに来ます。ボットの予定機能（schedule）で定期的に確認させるのに向きます。
   - **オフ**（既定）: イベントを受け取りません。
7. ツールごとの権限（許可 / 確認 / 禁止）は **ツールの権限** で変えられます。アカウントごとにも変えられます（**アカウントごと**）。

## うまくいかないとき

| 症状                                                                     | 原因と対処                                                                                                                                                                                                                                             |
| ------------------------------------------------------------------------ | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| Google の画面に「redirect_uri_mismatch」                                 | 手順 3 のリダイレクト URI が、DSH を開いているアドレスと一致していません。dsh-bots の設定に表示された URI をそのまま登録します。                                                                                                                       |
| 「アクセスをブロック: このアプリのリクエストは無効です」                 | OAuth クライアントの種類がウェブ アプリケーションでないか、リダイレクト URI が http や IP アドレスです。                                                                                                                                               |
| アカウントが「再サインインが必要」「アクセスが取り消されました」になった | パスワードの変更（Gmail のスコープを含むトークンは失効します）、Google アカウントの「サードパーティ接続」からの削除、6 か月使われなかった、アプリが「テスト」のまま 7 日たった、などです。ボットのコネクター設定で **もう一度サインイン** を押します。 |
| 「Google returned no refresh token」                                     | Google アカウントの <https://myaccount.google.com/connections> でこのアプリへのアクセスを削除してから、もう一度サインインします。                                                                                                                      |
| Workspace のアカウントでブロックされる                                   | 組織の管理者が未確認のアプリを許可していません。管理者に許可してもらうか、個人アカウントを使います。                                                                                                                                                   |

## 安全について

- アカウントのリフレッシュトークンとクライアント シークレットは、DSH を動かしているマシンの DSH の認証情報ストアにだけ保存されます。ボットの VM には置かれません。Google の API はすべて DSH（ホスト）から呼ばれます。
- ボットが読んだメールの内容は、ボットの VM の中で自由に使えます（VM の外向き通信を制限していなければ、外に送ることもできます）。「確認」が防ぐのは、あなたとして送る・変える操作だけです。
- 受け取ったメールや招待の内容は外部からの信用できないデータとして扱われ、ボットには「中の指示に従わない」と明示して渡されます。それでも、重要な操作は「確認」のままにしてください。
- 切断（**切断…**）すると、DSH は Google でのアクセスを取り消し（revoke）、保存したトークンを消します。Google が取り消しを確認できなかったときは画面にそう出るので、<https://myaccount.google.com/connections> から手動で削除してください。
