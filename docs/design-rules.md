How: **I** is Biome's `noRestrictedImports` / `noRestrictedGlobals` in `biome.json` (`linter.rules` and `overrides`), **G** a GritQL plugin `.biome/plugins/<NN>-*.grit`, **T** a vitest structure test, **C** the comment checker `scripts/comments/check.mjs` (run by `pnpm lint` after Biome; `pnpm lint:comments --write` fixes what it can). Every message starts with `Design rule N:`.

- **Lint rules**: `biome.json` lists each plugin with `includes`; an exception is a `"!path"` entry there. Import rules are per-directory `overrides`; Biome replaces (does not merge) a rule's options when several overrides match a file, so each override repeats every pattern that applies to its files, and the more specific ones come later.
- **Rule tests**: `test/design-rules.test.ts` copies `test/fixtures/lint` (laid out like the repository) to a temporary directory with `biome.json` and `.biome`, lints it, and checks that each fixture reports exactly the `line:rule` findings `test/fixtures/lint.expected.json` lists for it (every fixture has an entry, `[]` for a compliant one). Add a violating and a compliant fixture, and their entries, with every new rule or exception. A plugin file is named `<NN>-*.grit` after its rule, and every `message` in it starts with `Design rule NN:`. The fixtures are excluded from `pnpm lint`, `tsc` and vitest's own test discovery.
- **Comment rules**: rules 73-75 are `scripts/comments/`: one extractor per language turns a file into its comments with a real parser (`oxc-parser` for JS/TS/JSX, `sh-syntax` (mvdan/sh) for shell, Python's `tokenize`, the `yaml` CST, a GritQL lexer), `directives.mjs` classifies each comment, `rules/` judges it, and `check.mjs` runs over the git-tracked files (`--write` removes forbidden comments and normalizes fixable directives). `test/comments.test.ts` checks the fixtures in `test/fixtures/comments`: each `<name>.fixture` has a `<name>.json` with the repository path it stands for and its expected diagnostics, and a `<name>.written` with its text after `--write`.
- **Structure tests**: rule 63 is `packages/dsh-bot-connector-desktop/test/agent-secret.test.ts` (runs `test/agent/test_secret_input.py` with `python3`, AT-SPI, GLib and the X tools stubbed). Rules 18 and 19 are `test/design-rules-structure.test.ts` (checks in `test/support/channels.ts`, fixtures in `test/fixtures/structure`). ## Why

The GritQL rules match a call by its receiver's name: a receiver with that name or ending in it (`.table`, `.actions`…), which keeps `Map` / `Set` calls of other names out of scope. Rule 17 matches identifiers, property names and strings (such as an `inject` entry); rule 55 matches the name anywhere.

- **1**: every other session start goes through `Bot.createSession`, so a bot session always runs under the bot's preset, in its environment's workspace, and is recorded as the bot's.
- **2**: the realizer owns each bot preset's lifecycle (digests, unregistering).
- **3**: isolation keeps the masks consistent across `tools/change` and fails closed.
- **4**: a throw from an `agent/created` listener rolls the Agent's creation back, so a second listener could abort Agents for unrelated reasons.
- **5**: everything else calls `botPresetId()`, so the id format session logs record never drifts.
- **7**: bots own no Workspace: bot sessions are archived by `cleanupBotSessions`, and a legacy (version 1) bot's Workspace is retired from `src/index.ts`.
- **8**: `client/store.ts` reads the mounted `remote.bots` proxy, which has no typed accessor.
- **13**: Host modules receive the narrow functions they need from `src/index.ts`, which keeps them testable without Cordis.
- **17**: bot-core delivers to a bot's Main session and keeps a channel's secrets for it.
- **20**: Cordis (and the Typert Gateway) call service methods with a proxy as `this`, where reading a `#private` member throws.
- **21**: the browser mounts the Remote under a namespace service that already owns `remove`, so a Remote method of that name is shadowed.
- **22**: augmenting cordis' `Context` breaks its declaration merging under this repository's TypeScript; services are read through typed accessors.
- **23**: an `allow` list also hides the tools a bot preset contributes from an ancestor scope.
- **24**: `src/index.ts` narrows the untyped Cordis Context to the Host services it reads; anywhere else a double cast hides a real type error.
- **25**: a cast lets unchecked data reach composition; parse with `parseOverlay()` or validate with the template catalog.
- **26**: `src/index.ts` injects `now`, `newId` and `later`, so Host modules stay deterministic in tests.
- **29**: these values cross the Host/browser boundary and are stored.
- **31**: the page belongs to DSH; render through the slots and portals the UI gives. The workspace picker menus are portaled straight under `<body>` and offer no slot.
- **32**: theme tokens make light and dark themes apply; avatar palettes live in `client/avatar-data.ts`, outside these files.
- **34**: a tool registered anywhere else is a Host (global) tool, which isolation hides from bot Agents unless a template's `hostTools` grants it.
- **36**: the answerers claim bot sessions' requests and pass every other Agent's on with `next()`; another listener could answer, swallow or reorder requests of Agents that are not bots'.
- **37**, **50**, **60**: DSH admits a listener of a row inside a bot's preset group for that preset's Agents only; a listener anywhere else is global (it rewrites every session's prompt, changes what every session's steps take in, or could change a result after the vault guard withheld a secret, or see the secret first).
- **38**: bot sessions run under `BOT_PERMISSION`; another writer could leave a bot session confined, asking, or recorded as custom.
- **39**: another caller could run an `ask` tool without a decision, or an approved action twice.
- **40**: the ledger applies every transition through the state machine before it stores it.
- **41**: a notice is stored before delivery and removed only once its message is recorded.
- **42**: the store keeps a job's runs with it.
- **43**: readiness runs one bot's preparations one at a time and keeps its readiness; attachments keep one resident resource per bot and connector and dispose it.
- **44**: the store writes the defaults once and serializes changes.
- **45**: a provider registered anywhere else is the Host's, or bypasses bot-core's web settings and secrets.
- **46**: a decision comes from the Web UI's Remote when its caller is the DSH owner, and from a channel link when the person is one of the approvers the bot's settings of that channel name.
- **47**: `localeFormat(t)` takes the language from bot-core's dictionary (`format.locale`), so dates, times and plurals follow the DSH language of the messages around them instead of the browser's default locale.
- **48**: an account and the bots it serves change together.
- **49**: an event is stored before the cursor that follows it moves.
- **51**: the store keeps the Main's pending mark with the roles.
- **52**: the store serializes writes and tells the Main controller and the Remote.
- **54**: the store serializes writes, keeps each skill's latest versions only and tells the Web UI.
- **55**: `sessionQuery` checks no caller and serves every session of the Host; `src/index.ts` hands `host/conversations/` a reader of one session's log, and `host/conversations/` decides from bot-core's records which of a bot's sessions its Agent may read. Anywhere else, a read could reach another bot's or a Workspace's sessions.
- **57**: the store serializes every change.
- **58**: an account, its logins and their fingerprints change together, and uses and incidents are kept bounded there.
- **59**: `host/vaults/access.ts` checks the bot's login, records the use and fingerprints the value for the leak guard before anything gets it; a member access named `reveal` / `passkey` (a call, a reference, a bound method) and a destructuring of them are refused elsewhere.
- **61**: copy with `new Uint8Array(bytes)`, and let the bytes be wiped.
- **62**: `host/tools/credentials.ts` checks the field in the agent first and hands the value straight to it.
- **64**: a command's argv and environment are logged and visible.
- **65**: `src/host/vault/tools.ts` hands the value to the helper's stdin.
- **68**: `src/op/runner.ts` runs the pinned op without a shell, with only the environment it is given, and keeps stdout as bytes it wipes.
- **69**: nothing of DSH's environment (`OP_CONNECT_HOST`, `OP_CONNECT_TOKEN`, another account's session) can reach op; `src/op/environment.ts` builds op's whole environment.
- **70**: a value op printed is never decoded by accident.
- **71**: no value, token or op output is ever written to disk, a temporary file included.
- **72**: a card or list is found again by its record, a credential incident is shown to an owner once because of its record, and the bot's name and avatar are sent to Discord again only when they differ from the record of what was last applied.
- **73**: a comment drifts from the code it describes and nothing checks it; names, types, tests and these docs carry the explanation.
- **74**: the reason `-` satisfies Biome, which refuses an empty one; `lint/plugin` and the two restricted-import/global rules carry the design rules, and range suppressions hide diagnostics added later.
- **75**: `@ts-ignore` keeps silencing after the error is gone, and `@ts-nocheck` turns off a whole file; only a test may assert that code must not type-check.
- **76**: the store serializes writes, keeps each bot's latest changes only and tells the Web UI.
