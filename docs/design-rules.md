How: **I** is Biome's `noRestrictedImports` / `noRestrictedGlobals` in `biome.json` (`linter.rules` and `overrides`), **G** a GritQL plugin `.biome/plugins/<NN>-*.grit`, **T** a vitest structure test. Every message starts with `Design rule N:`.

- **Lint rules**: `biome.json` lists each plugin with `includes`; an exception is a `"!path"` entry there. Import rules are per-directory `overrides`; Biome replaces (does not merge) a rule's options when several overrides match a file, so each override repeats every pattern that applies to its files, and the more specific ones come later.
- **Rule tests**: `test/design-rules.test.ts` copies `test/fixtures/lint` (laid out like the repository) to a temporary directory with `biome.json` and `.biome`, lints it, and checks that exactly the lines ending in `// rule: N` are reported. Add a violating and a compliant fixture with every new rule or exception. The fixtures are excluded from `pnpm lint`, `tsc` and vitest's own test discovery.
- **Structure tests**: rules 18 and 19 are `test/design-rules-structure.test.ts` (checks in `test/support/channels.ts`, fixtures in `test/fixtures/structure`). Rule 27 is `packages/dsh-bot-core/test/bots-domain-schema.test.ts` with one snapshot per domain in `test/__snapshots__/` (`bots-domain.schema.snap`, `channels-domain.schema.snap`, `connectors-domain.schema.snap`, `managed-sessions-domain.schema.snap`, `models-domain.schema.snap`, `notices-domain.schema.snap`, `onboarding-domain.schema.snap`, `schedules-domain.schema.snap`, `web-domain.schema.snap`, `vaults-domain.schema.snap`); after a compatible change (a new optional field) or a version bump, run `pnpm vitest run packages/dsh-bot-core/test/bots-domain-schema.test.ts --update`.
