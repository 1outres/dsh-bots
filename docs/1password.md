# 1Password のログイン情報をボットに使わせる

この手順で、ボットが 1Password の項目（ログイン）を使ってサイトやアプリにログインできるようになります。
ボットが使えるのは **あなたがボットごとに選んだ項目と、その中で許したフィールドだけ** で、パスワードやワンタイムコードの値はモデルに渡りません（docs/specs/bot-vaults.md）。

必要なもの:

- DSH に `@1outres/dsh-bots` バンドル（または `@1outres/dsh-bot-core` と `@1outres/dsh-bot-vault-1password`）が入っていること。DSH が動くのは Linux か macOS（amd64 / arm64）。
- 1Password のアカウント（個人・ファミリー・Teams・Business のどれでも）。サービスアカウントを作れるのはアカウントの所有者・管理者です。
- DSH の Host から `https://cache.agilebits.com`（初回だけ、1Password CLI の取得）と 1Password のサーバーに https で届くこと。

扱えるのは **パスワードとワンタイムコード（TOTP）** とユーザ名です。**パスキーは使えません**（1Password は SDK・CLI・Connect のどれでもパスキーの秘密鍵を取り出させないため）。dsh-bots は 1Password に何も書き込みません。

## 1. ボット用の Vault を作る

1. 1Password（アプリか `https://my.1password.com` など）で **新しい Vault** を作ります（名前は例えば `Bots`）。
2. ボットに使わせるログインだけをこの Vault に入れます（自分用の項目をコピーするより、ボット用のアカウントを作ってそのログインを入れるのがおすすめです）。
   - 項目の種類は **ログイン** か **パスワード**。ほかの種類は一覧に出ません。
   - ワンタイムコードを使わせるなら、項目に **ワンタイムパスワード** のフィールドを足します。
   - 項目の **ウェブサイト** に入れた URL の https の origin が、ボットが入力してよいサイトの既定になります。

サービスアカウントには、作ったあとで Vault を足せません。Vault を先に作ってください。

## 2. サービスアカウントを作る

1. `https://my.1password.com/developer-tools/infrastructure-secrets/serviceaccount`（**開発者 → サービスアカウント**）を開き、**サービスアカウントを作成** を押します。
2. 名前（例: `dsh-bots`）を付けます。**Vault の作成を許可しない** ままにします。
3. Vault の選択で **1. の Vault だけ** を選び、権限は **読み取り** だけにします（書き込み・共有は付けません）。
4. 作成するとトークン（`ops_…`）が一度だけ表示されます。コピーして次の手順で使います（1Password に保存しておくこともできます）。

トークンは Vault の読み取りに使われるので、漏れたら 1Password の同じ画面でサービスアカウントのトークンを取り消し、作り直してください。

## 3. DSH につなぐ

1. DSH の Web UI で dsh-bots の設定 → **パスワード管理** を開きます。1Password の状態が **準備完了** になるのを待ちます（初回は 1Password CLI を取得・検証します。失敗したら理由が出ます）。
2. 1Password の **口座を追加** で、名前と 2. のトークンを入れて保存します。トークンは DSH の資格情報ストアに保存され、画面には二度と出ません。
3. ボットの設定 → **ログイン情報** で **追加** を押し、口座を選んで項目を検索し、使わせる種類（ユーザ名・パスワード・ワンタイムコード）、サイト、デスクトップでの入力の可否、ボットに見せる名前を決めて保存します。

## 制限

- 1Password はサービスアカウントの読み取り回数を制限しています（個人・Teams はトークンごとに 1 時間 1,000 回、ほかにアカウントの 1 日の上限）。入力 1 回で 2 回（項目と値）、項目の検索で「Vault の一覧 + Vault ごとの一覧 + 変わった項目ごとに 1 回」を使います。上限に達すると、その旨のエラーになります。
- 1Password CLI は dsh-bots が版を固定して取得・検証したものだけを使い、PATH の `op` は使いません（packages/dsh-bot-vault-1password/README.md）。

## 本物のアカウントで確かめる（開発者向け）

テストは偽の `op` で行っているので、本物のサービスアカウントでは次を確かめてください（動作確認用の DSH で）。

1. 上の 1.〜3. のとおりにつなぎ、口座の識別（アカウントの URL）が出ること。
2. ログイン情報の追加で、項目が検索でき、ワンタイムパスワードのある項目にはワンタイムコードが選べること。
3. ブラウザのコネクターで、パスワードとワンタイムコードが入力できること（`op read` の ID 指定と `?attribute=otp`）。
4. サービスアカウントのトークンを取り消すと、入力が「1Password did not accept the service account token」で失敗すること。
5. 項目を Vault から消すと、ログイン情報が missing と表示されること。
