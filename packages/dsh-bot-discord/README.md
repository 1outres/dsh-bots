# @1outres/dsh-bot-discord

Talk with each bot of DeepSeek Harness in Discord, at one **home**: direct messages with its owner, or one server text channel. Every bot gets its **own** Discord bot (its own token); the plugin (row `bot-discord`, `inject = ["bot", "storageDomain"]`) registers the `discord` channel with `@1outres/dsh-bot-core`, which keeps the settings and connects each configured bot (see bot-core's README, "Channels"). The design is docs/specs/bot-discord-home.md.

## Behavior

Its owners field is **Owners** (key `approvers`, kept from when it named connector approvers only), and its `formatHint` tells the bot that Markdown renders, tables do not, and `<>` keeps a link from expanding. The channel declares (`DISCORD_CAPABILITIES`): up to 10 attachments of up to 500 MiB per message (bot-core's own limits are lower), files up to 10 MiB (a bot's upload limit outside a boosted server), turn states, the `stop`, `status` and `new` commands (and its own `/pending`), connector actions and credential incidents, and every interaction kind (`question`, `approval`, `plan-review`).

- **One home** (`src/host/home.ts`). _Direct messages_: one person, the one owner, talks with the bot in their DMs. _A server channel_: everyone who can see that text channel talks with the bot there (who can is up to Discord's invites, roles and channel permissions); the owners are people who can see it. Everything the bot posts goes to the home and nowhere else (`src/host/home-target.ts`): replies, files, turn notices, typing, question, approval and plan review cards, connector action cards, the pending list and credential incidents. In a channel home everyone there sees the contents of connector actions waiting for approval (an email's text…) and the incident reports; the home field's description says so.
- **What reaches the Main session** (`src/host/inbound.ts`). In DM mode, the owner's DMs only (anyone else's DM is dropped without an answer); in channel mode, messages posted directly in the home channel by anyone but bots and the bot itself (threads, other channels and DMs are dropped). Only `DEFAULT` and `REPLY` messages count. A message goes to the Main session the way DSH's Web composer sends a plain Enter (bot-core's `deliver`), with the place (`direct`, or `channel` with the channel's and the server's names) and the sender: the Discord user id, the display name (the server nickname in a channel, else the global name, else the username) and the username as handle, and whether the account is a bot; bot-core writes the header (`[Discord · DM · Alice (@alice, owner)]`, `[Discord · #general (Team) · Bob (@bob)]`) and marks the owners. Messages are delivered one at a time, in arrival order, each at most once (in id order). When the Gateway has to start a new session instead of resuming, the home is read for the messages posted meanwhile, which are delivered before newer ones. Once the Main session accepted it, the message gets a 👀 reaction; when it was not delivered it gets ⚠️ and a reply saying why.
- **Attachments** are passed with their declared name, size and type; bot-core reads them from Discord's CDN only once it accepted them (`src/host/download.ts`: HTTPS `cdn.discordapp.com` / `media.discordapp.net` only, no redirects, stopping past the limit): images become image parts as in DSH's composer, other files are saved in the bot's `<workspace>/.inbox/` and named in the text. Stickers and embeds are not passed.
- **Replies.** Every assistant message the Main session commits with text (whoever started the turn) is posted at the home, made Discord-safe (`src/host/format.ts`: Markdown tables become aligned code blocks, wide characters counted twice; headings below `###` become bold lines; horizontal rules a line Discord shows; code blocks are left alone) and split into messages of at most 2000 characters. Reasoning and tool calls are not sent; mentions never ping (`allowed_mentions: { parse: [] }`).
- **Files.** A file the Main session presents with `present` is uploaded at the home after the turn's last reply, with its description as the caption; when Discord refused it, bot-core tells the Main session.
- **Turn notices and typing.** A failed turn ("⚠️ The reply failed: …") and a stopped or interrupted one ("⏹️ Stopped.") are told at the home, in the **Notice language**. While a turn runs, the home shows "typing", refreshed every 8 s and again 1.5 s after a reply; it stops when the turn ends.
- **Questions, approvals and plan reviews** (`src/host/interactions/`). Each interaction gets one card at the home (an embed and components), in the **Notice language**, in order with the replies; a plan (and a question's detail longer than 1500 characters) is posted first as messages of its own. The card has one draft: whoever presses moves the same draft on. A question is answered by anyone at the home (in DM mode that is the owner); an approval and a plan review by the owners only — anyone else gets a private refusal. A press away from the home gets a private refusal too.
  - _A question batch_ shows one question per page (`n/N`) with its choices listed: up to 5 single-select choices as buttons, otherwise select menus of 25, up to 4 menus (100 choices). **Other…** / **Answer…** opens a form (a modal, up to 4000 characters), **Skip**, **Back**, **Next**, **Submit**. A timed batch shows when the bot goes on (a Discord timestamp), **Take time**, and later "waiting until you answer" or "the bot went on; you can still answer"; any choice, form or Take time holds the countdown.
  - _An approval_ offers **Reject**, **Allow once** (or the asker's wording) and **Always allow** only when the asker offers it. _A plan review_ offers **Approve** and **Request changes…** (a form with optional feedback).
  - A custom id is `dshb:<interaction id>:<action>` (positions, never labels). A pressed card shows "Sending…" at once, then the closure; a refused answer shows why and stays answerable. Once the interaction closes, the card shows who answered and what, or that it was withdrawn, with every component disabled. A card posted before a reconnection still answers while its interaction is open.
- **Connector actions** (`src/host/actions/`). A connector action that asks first is posted at the home as a card: the preview's title, the connector and tool, the fields and the body as typed (escaped, the body in a code block a fence inside cannot close, cut at the embed's 4096 characters), when it was requested and when it expires, with **Approve** and **Reject** (custom id `dshc:<action id>:a|r`). A press goes to bot-core (`link.decide` with the presser's Discord user id), which takes it only from an owner: anyone else gets a private refusal and the card stays. The card then follows the action wherever it was decided, without buttons once it is no longer pending. Where the card sits is stored, so a new connection edits it instead of posting it again, and brings up to date the cards of actions that ended or were dropped meanwhile (`link.connectorAction`). A card deleted in Discord is posted again while its action is pending.
- **Pending approvals list.** The home holds one message listing the bot's pending actions (`link.openActions`), oldest first, one line each: the title linking to its card, the connector and tool, and when it expires, under "📋 Pending approvals of <bot> (N)". It is edited whenever it changes, pinned once right after it is posted (a refused pin is logged and not tried again for that message), and posted again when it was deleted.
- **Credential incidents** (`src/host/incidents/`, docs/specs/bot-vaults.md §7.3). Each incident bot-core sends gets one card at the home, in the **Notice language**: a headline naming the bot (🔒 withheld, 🚨 exposed), the login's name and kind, where, when, and the outcome, ending by pointing to the Web UI to acknowledge it. bot-core sends unacknowledged incidents again to every new connection; a record per incident and home keeps the home from seeing one twice, and one whose card could not be posted is posted at the next connection.
- **Stored.** The storage domain `dsh_bot_discord` (`src/host/domain.ts`, version 3 reading versions 1 and 2, `backup-and-skip`): `cards` (`<bot>:<action>`), `digests` (`<bot>`, with the pin state `due` / `pinned` / `abandoned`) and `incidents` (`<bot>:<incident>`), each with the home channel it sits in. Version 2 kept them per person (`…:<user>`); each connection adopts, under the new keys, the bot's records that sit in its home's channel and forgets the others (`adoptApprovalRecords`, `adoptIncidentNotices`), so after an upgrade the owner's DM home keeps its cards and other DMs' cards are no longer followed. Only `src/host/actions/records.ts` and `src/host/incidents/records.ts` write them (design rule 72). `test/domain-schema.test.ts` snapshots the schema.
- **Slash commands.** `/stop`, `/status`, `/new` and `/pending` are registered as global commands on every new Gateway session (`contexts: [BotDM]` in DM mode, `[Guild]` in channel mode), with bot-core's descriptions. They run at the home only; anywhere else (another channel or server, someone else's DM) they get a private refusal. Who may run them is bot-core's (`/new` for the owners). `/pending` answers an owner privately with the list, and anyone else with a refusal that shows nothing of the actions.
- **Connection.** One [discord.js](https://discord.js.org) client per bot. DM mode: intent `DirectMessages` only (no privileged intent), partial `Channel`. Channel mode: `Guilds`, `GuildMessages`, `MessageContent` and `GuildMembers` (both privileged), no DMs. When the Portal has a privileged intent off, Discord closes with 4014 and the state says which intents to turn on where. A rejected token or another unrecoverable close stops the bot for good and shows "Failed"; a login that cannot reach Discord is retried with a new client after 1 s, doubling to 60 s. Once connected, the state carries the owners' names (`src/host/people.ts`: the server member in channel mode, the user in DM mode), so the bot's status names them. The token never appears in logs.

## Settings (bot menu > Channels > Discord)

Nothing is typed but the token: the home and the owners are picked from what Discord tells with the token, over REST, before any connection (`src/host/settings/queries.ts`, `src/host/discordjs/lookup.ts`).

| Field           | What                                                                                                                                                                                                                                                                                                                                                                                                            |
| --------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Bot token       | Secret, required. Stored in DSH's credential store; the browser only learns whether it is set.                                                                                                                                                                                                                                                                                                                  |
| Home            | Required (`home`: `dm` or `<guildId>:<channelId>`). Options: **Direct messages**, then every text channel of the servers the bot is in where it can view, post and read history (`#name (Server)`). Suggested: Direct messages. Changing it empties Owners in the same save (their options follow the home).                                                                                                    |
| Owners          | Required, 1–10 (key `approvers`). Options: in DM mode the application's owner (a team's members, its owner first); in channel mode the members who can see the home channel, bots left out, the application's owners first (needs Server Members Intent; up to 5000 members are read). Suggested: the application's owner (a team's owner). A stored owner who is not among the options is still shown by name. |
| Notice language | Optional, Default (English), English or 日本語 (stored `""`, `en`, `ja`): the bot's own texts at its home. Command answers and private refusals follow each user's Discord language.                                                                                                                                                                                                                            |

Beside the fields the form shows the bot's account, **Invite the bot to a server** (`scope=bot applications.commands`, with View Channel, Send Messages, Read Message History, Embed Links, Attach Files, Add Reactions and Pin Messages), a link to the bot in the Developer Portal, and, for a channel home, a warning for each of Message Content and Server Members Intent the Portal has off. Suggestions are proposed, never saved until picked. bot-core asks the channel to check enabled, complete settings before saving them: in DM mode exactly one owner; in channel mode the bot can view, post and read the home channel, and every owner is a member who can see it. Settings stored by version 1 of this plugin (allowed users and owners in DMs) are upgraded once (`src/host/upgrade.ts`): the home becomes direct messages with the first owner who was also an allowed user, else the first owner, else the first allowed user; the others are dropped and logged.

## Discord setup

1. [Discord Developer Portal](https://discord.com/developers/applications) > **New Application** (one per DSH bot).
2. **Bot** > **Reset Token**, and set it as the bot's token in DSH (the bot's menu > **Channels** > Discord, or the welcome guide).
3. Invite the bot with the **Invite the bot to a server** link the settings show. For direct messages, a server you share with it is enough (Discord only lets a user and a bot exchange DMs when they share a server).
4. For a server channel home, turn on **Message Content Intent** and **Server Members Intent** under **Bot** > **Privileged Gateway Intents**.
5. Pick the **Home** and the **Owners**, and turn Discord on (each setting is saved as you change it). The state turns to "Connected" with the bot's name. Write to it at its home.

## Structure

| Module                                                                                                                                                                           | What                                                                                                                                                                                                                                                                                                                                    |
| -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `src/host/discord.ts`                                                                                                                                                            | The contract the logic uses: plain message data, client events (`ready` for a new Gateway session, `resumed`, `reconnecting`, `message`, `command`, `failed`), actions (`openDm`, `send` with files and a reply target, `react`, `typing`, `messagesAfter`, `registerCommands`) and the REST lookup the settings use (`DiscordLookup`). |
| `src/host/discordjs/`                                                                                                                                                            | The discord.js adapter, the only code importing discord.js (design rule 33): client options and sharding (`options.ts`, `sharding.ts`), mapping to the contract (`messages.ts`, `commands.ts`), failures (`failures.ts`), events and actions (`client.ts`).                                                                             |
| `src/host/connection.ts`                                                                                                                                                         | Keeps a bot logged in: reports the state, replaces a client that failed retryably.                                                                                                                                                                                                                                                      |
| `src/host/bridge.ts`                                                                                                                                                             | DMs to the Main session and bot-core's outputs back: ordering, catch-up after a new session, reactions and failure replies, files, turn notices, typing, slash commands.                                                                                                                                                                |
| `src/host/interactions/`                                                                                                                                                         | Interaction cards: custom ids (`custom-id.ts`), the card's shared draft (`draft.ts`), the cards, pure (`render.ts`, `texts.ts`), and presses and forms answered through bot-core (`presenter.ts`).                                                                                                                                      |
| `src/host/actions/`                                                                                                                                                              | Connector action cards and the pending approvals list: custom ids, the card and the list, pure (`render.ts`, `digest.ts`, `texts.ts`), the stored records (`domain.ts`, `records.ts`), the home's list (`digests.ts`), cards, presses and `/pending` (`presenter.ts`, `command.ts`).                                                    |
| `src/host/incidents/`                                                                                                                                                            | Credential incident cards: the card, pure (`render.ts`, `texts.ts`), which incident the home was shown (`domain.ts`, `records.ts`), posting each once at the home (`presenter.ts`).                                                                                                                                                     |
| `src/host/domain.ts`                                                                                                                                                             | The storage domain `dsh_bot_discord` and its tables.                                                                                                                                                                                                                                                                                    |
| `home.ts`, `home-target.ts`, `inbound.ts`, `download.ts`, `format.ts`, `texts.ts`, `cursor.ts`, `split.ts`, `typing.ts`, `queue.ts`, `people.ts`, `permissions.ts`, `upgrade.ts` | The home and where it posts, what a message at the home brings, reading attachments, Discord-safe Markdown, the bot's own texts (en/ja), the newest message taken per channel, splitting at 2000, the typing generation, serial queues, the owners' names, channel permissions, the settings upgrade.                                   |
| `src/host/settings/`                                                                                                                                                             | The settings form's answers: options of the home and the owners, the cross-field check, the inspection (account, invite, intent warnings), over the REST lookup.                                                                                                                                                                        |

Everything outside `src/host/discordjs/` is library-independent and tested with fakes of the contract; the adapter is tested against a real discord.js `Client` with REST and login stubbed. A new Discord feature adds its events and actions to `discord.ts` (buttons, select menus, modals and embeds are there: `component`, `modal`, `send` returning the message id, `edit` and `remove` telling a message that is gone, `pin` telling why Discord refused) and implements them in the adapter (`discordjs/components.ts`). Neither half touches the Host's files or processes (design rule 35); the composition root (`src/index.ts`) wires the timers, `fetch` and the storage domain.

**Not supported:** tool calls or reasoning as they happen, progress, edits and deletions in Discord, sessions other than Main, more than one home, threads and group DMs, pairing codes, sign-in flows, changing settings from Discord, stickers, polls and voice. A card's draft lives in the connection: after a reconnection of the plugin (a settings change, a restart) open interactions are posted again.

discord.js is a `dependency` of this package (`^14`): installing the plugin or the `@1outres/dsh-bots` bundle installs it into the profile next to the plugin, while builds keep it external (`test/packages-bundle.test.ts` checks that `lib/` holds only this package's code and imports only declared packages). discord.js and its dependencies run no install scripts; its optional native accelerators (`zlib-sync`, `bufferutil`, `utf-8-validate`) are not needed and not installed.

## Requirements

`@1outres/dsh-bot-core` with DSH's credential store (`ctx.credentials`) and storage domains (`ctx.storageDomain`), both part of the default composition, and Node.js 22 or newer. Install a packed tarball together with bot-core, as for `@1outres/dsh-bot-vm`; pnpm installs discord.js with it.
